# Evidence from our run

Supporting files for the claims in [`../REPORT.md`](../REPORT.md), collected from
`$WORKDIR/out` by [`scripts/tools/collect-evidence.sh`](../scripts/tools/collect-evidence.sh).
Text files are copied as produced, except that colour codes are stripped and the machine's
hostname is replaced with `<host>`.

The evidence of our earlier run on the original library is on the branch
[`original`](https://github.com/gmailbob/verify-RH-Lean/tree/original/evidence).

Only small files go here: those that back a claim directly, or that would take a reader a
long time to regenerate.

| File | Produced by | Backs |
|---|---|---|
| `machine.txt` | collector | the machine every timing refers to |
| `logs/00-check-machine.log` … `logs/09-independent-kernel.log` | each step | every PASS/FAIL line in REPORT's "Results by step". Some logs contain several runs of a step, appended. |
| `logs/extra-depgraph.log` | `scripts/extra/depgraph/run.sh` | the dependency-graph export |
| `scan/scan.txt`, `scan/scan.json` | step 3 | no `sorry`, axioms, `unsafe`, `native_decide` and so on in code; the inventory of attributes and options |
| `build/build-summary.txt`, `build/build-monitor.csv`, `build/build-time.txt` | step 5 | the build result; time, disk, memory and mapping count every 30 s; the largest single process |
| `build/build.log` | step 5 | Lake's full output: every project module built, and the 10 warning lines |
| `build/project-oleans.sha256.zst` | collector, from the build | sha256 of each of the project's 1,606 compiled files, so anyone can compare builds without building. Files that embed the absolute source path differ between machines. |
| `audit/selftest.txt` | step 6 | the audit checks accept good declarations and reject each kind of cheat |
| `audit/statements.txt` | step 6, before the build | statements identical to `scripts/audit/Reviewed.lean`, using only Mathlib/core |
| `audit/audit.txt` | step 6, after the build | the five theorems' types and axioms |
| `replay/replay.log`, `replay/replay-monitor.csv`, `replay/replay-progress.csv` | step 7 | the fresh kernel replay: exit status, time, memory |
| `independent-kernels/solution.ndjson.sha256` | step 9 | the sha256 of the export of our build |
| `independent-kernels/con-leche.log`, `con-ron.log`, `nanoda.log` | step 9 | each independent checker's verdict, time and memory |
| `proof-structure/depgraph-report.txt`, `depgraph-meta.txt`, `proof-tree.txt` | `scripts/extra/` | the proof-structure analysis |

Two things in the logs that are not results:

- `logs/09-independent-kernel.log` contains an earlier attempt in which con-leche and con-ron
  stopped at once on a command-line option of ours that they do not accept (exit 3, a usage
  error). The later run in the same log is the result.
- `logs/05-build.log` has 17 lines ending in `/proc/<pid>/maps: No such file or directory`. They
  come from the resource monitor, when a Lean process had exited just as its mapping count was
  read. They do not concern the build, and `scripts/lib.sh` no longer prints them.

## Not included, and why

| Output | Why it is not here |
|---|---|
| The source and its hash lists | regenerated by step 2 from the public repository in seconds; the digest is pinned in `config.sh` |
| The export (`solution.ndjson`) | large, and step 9 regenerates it from the build; its sha256 is kept |
| The dependency graph (`nodes.tsv`, `edges.bin`) | `scripts/extra/depgraph/run.sh` regenerates it |
| The build itself (`.lake/`) | regenerate with step 5 |
